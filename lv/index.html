Pros and cons

Better

  • Faster, most of all on a slow day.
  • A change reaches GitHub already checked, so fewer fix-and-push rounds.
  • No waiting for GitHub's machines, no paid minutes, and nothing checked twice.
  • It can watch the live site after a deploy, started by hand for now.

Worse

  • One server: if it is down, nothing gets checked, and keeping it running is my job.
  • Checks that need Docker or a database can't run there yet.
  • Apple app builds take turns on one Mac.
  • Picking only the touched checks could miss something; it runs everything when unsure.

Moving a repo over

A repo switches when LV and Actions agree on at least one replayed commit, disagree on none, and LV never errors. The one exception is a disagreement the repo causes itself, such as a flaky test: it gets explained before the switch, not ignored.

GitHub Actions ran 1,260+ hours of workflows for 11 of my repos in the last 30 days.
